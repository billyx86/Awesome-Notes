# Awesome-Notes

A Flutter app skeleton for a notes app: email/password auth with
Firebase Authentication (including email verification), a route table,
and a notes screen. The notes feature itself is still a placeholder
(see [Status](#status)).

## Screens

- **Login** — email + password, with a "Create an account" CTA.
- **Register** — creates the Firebase account and sends the user to the
  email-verification screen.
- **Verify email** — re-sends the verification email.
- **Notes** — currently a `Hello World` placeholder with a logout menu.

Unauthenticated users land on Login; a signed-in but unverified user
lands on Verify email; a verified user lands on Notes.

## Status

- Firebase auth (login / register / verify email / logout) is wired up.
- The notes feature is **not** implemented — `NotesView` renders a
  `Hello World` placeholder. `cloud_firestore` is already a dependency
  if you want to build on it.

## Getting started

1. Install **Flutter 3.7.12** (or any release with Dart
   `>=2.19.6 <3.0.0`) and add it to your `PATH`.

   ```sh
   flutter --version
   # Flutter 3.7.12 ...
   # Tools • Dart 2.19.6 ...
   ```

2. Fetch dependencies:

   ```sh
   flutter pub get
   ```

3. Run it:

   ```sh
   flutter run
   ```

> The app builds and its tests run out of the box **without** any
> Firebase project — see the note below before you expect sign-in to
> actually work.

## Firebase setup

`lib/firebase_options.dart` is committed as a **placeholder** with
obviously-fake values (project id `awesomenotes-placeholder`,
`AIzaSyPLACEHOLDER_...` keys). That exists on purpose: the file is
normally generated by FlutterFire and gitignored, which made fresh clones
fail to compile with `uri_does_not_exist`.

To make sign-in actually work:

1. Create a Firebase project at
   <https://console.firebase.google.com> and enable **Email/Password**
   under Authentication → Sign-in method.
2. Register your app(s) (Android / iOS / Web) in the project.
3. Install the FlutterFire CLI and generate real options:

   ```sh
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```

   This overwrites `lib/firebase_options.dart` with your real values.
4. If you would rather keep your (client-side, publicly visible) Firebase
   keys out of git, re-add the commented line for
   `/lib/firebase_options.dart` under "Firebase config" in `.gitignore`
   and run `git rm --cached lib/firebase_options.dart`.

Without a real project, the UI renders but Firebase calls will fail
against the placeholder configuration.
